# Reproducible GSL candidate build

`Native-GSL` builds GNU GSL 2.8 using vcpkg commit e456309491fd875487bf02b8a0dca76c1b1b00cc, port revision 2, with the reviewed GNU archive SHA-512. No floating tool checkout or unreviewed prebuilt binary cache is used. The GNU upstream website could not be reached during initial review; 2.8 is the verified port candidate, not an unsupported claim about the absolute latest upstream release.

`./build.ps1 -Target Native-GSL-Validate` builds native libraries, CBLAS and C ABI/numerical probes on the host OS; it then runs a managed .NET ABI probe against the staged artifacts. On Windows it also runs the complete existing numerical suite and desktop suite against this candidate. Existing normal CI still uses the original embedded binaries, providing a separate old/new comparison against the same expected results. No expected values, skips or tolerances are changed.

Supported build recipes: Windows x64, Linux x64, macOS ARM64/x64. Output is `artifacts/gsl/<rid>/native`, including `gsl-provenance.json`, SHA-256 for each file, source/toolchain metadata and the GSL license. Native binaries are CI artifacts, not silently committed vendored blobs. Copying this inventory is not a signature or a defense against someone able to replace both the library and its manifest; use only trusted build artifacts. Distribution must include the corresponding source, build instructions/patches and notices required by the upstream license, not just the DLL.

To test on Windows, set an **absolute** `COMPUTATOR_GSL_DIRECTORY` to the staged win-x64/native directory before starting the process. Hash/architecture/version errors fail closed instead of falling back to an unrelated library. The old embedded payload remains the default until candidate acceptance. This does not make the Windows desktop/Core graph portable; Mac/Linux probe success is native-library evidence, not Mac desktop support.

Release gates: review the three native jobs and Windows numerical results, independently validate difficult special-function inputs, review binary dependencies and compiler flags, and decide when to make the candidate the default packaged runtime. The legacy ThrowException error callback still crosses a native boundary and needs a separate wrapper-wide status-return migration before claiming hardened error semantics. New probes use `_e` status APIs with the process-aborting handler disabled. No ABI is guessed from renamed DLLs.

Primary sources: https://github.com/microsoft/vcpkg/tree/e456309491fd875487bf02b8a0dca76c1b1b00cc/ports/gsl ; https://www.gnu.org/software/gsl/ ; https://learn.microsoft.com/dotnet/standard/native-interop/best-practices
