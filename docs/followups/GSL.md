# Reproducible GSL build and packaged runtime

`Native-GSL` builds GNU GSL 2.8 using vcpkg commit e456309491fd875487bf02b8a0dca76c1b1b00cc, port revision 2, with the reviewed GNU archive SHA-512. No floating tool checkout or unreviewed prebuilt binary cache is used. The GNU upstream website could not be reached during initial review; 2.8 is the verified port candidate, not an unsupported claim about the absolute latest upstream release.

`./build.ps1 -Target Native-GSL-Validate` builds native libraries, CBLAS and C ABI/numerical probes on the host OS; it then runs a managed .NET ABI probe against the staged artifacts. On Windows it also runs the complete existing numerical suite and desktop suite against this build. Unit-test outputs without a staged payload retain the embedded baseline, providing an old/new comparison against the same expected results. No expected values, skips or tolerances are changed.

Supported build recipes: Windows x64, Linux x64, macOS ARM64/x64. Output is `artifacts/gsl/<rid>/native`, including `gsl-provenance.json`, SHA-256 for each file, source/toolchain metadata and the GSL license. Native binaries are CI artifacts, not silently committed vendored blobs. Copying this inventory is not a signature or a defense against someone able to replace both the library and its manifest; use only trusted build artifacts. Distribution must include the corresponding source, build instructions/patches and notices required by the upstream license, not just the DLL.

Normal Windows desktop, API, local web, MSI and MSIX packages now include the reviewed 2.8 payload, corresponding source/build material and notices under `native/gsl`; see [packaged acceptance](GSL-ADOPTION.md). Their checks verify the actual deployed resolver with `COMPUTATOR_GSL_DIRECTORY` cleared. For separate development experiments, an **absolute** override can still select a trusted staged directory. Hash/architecture/version errors fail closed instead of falling back to an unrelated library. This does not make the Windows desktop/Core graph portable; Mac/Linux probe success is native-library evidence, not Mac desktop support.

Release gates: review the final commit's three native jobs and Windows numerical results, independently validate difficult special-function inputs, and review binary dependencies, compiler flags and the matching source archive. The [managed error boundaries](GSL-ADOPTION.md) record native errors and translate them after the native call returns; raw status-return APIs remain preferable for new wrappers. Probes also use `_e` status APIs with the process-aborting handler disabled. No ABI is guessed from renamed DLLs.

Primary sources: https://github.com/microsoft/vcpkg/tree/e456309491fd875487bf02b8a0dca76c1b1b00cc/ports/gsl ; https://www.gnu.org/software/gsl/ ; https://learn.microsoft.com/dotnet/standard/native-interop/best-practices
