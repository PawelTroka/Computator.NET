# Web custom functions and JSON execution

The Custom Functions page is no longer a placeholder. Its Ace editor state is shared across routes in the current tab. Unsaved definitions are sent with each execution. Explicit Save stores a versioned copy in sessionStorage; reload restores it. Import/export uses UTF-8 `.tslf` files and does not change the desktop format. Browser sessions/tabs are not a server-side account system.

`POST /api/v2/execute` accepts `{operation, expression, customFunctions, x, y, a, b, n, order, epsilon, method}`. Operations are calculate, script, integral, derivative and function-root. Results are `{result: string}` in the existing mathematical display notation. `POST /api/v2/chart` accepts expression/definitions and width, height, xMin/xMax/yMin/yMax and returns PNG. Requests are bounded and validated; malformed programs receive problem details. Programs are data in the JSON body, never path segments, so `/`, Unicode and multiline definitions survive transport.

Each request has a fresh evaluator. No generated function object, definition string or mutable compiler state is cached across callers, including legacy GET requests. Legacy calculation/script endpoints remain for compatibility and decode source segments exactly once from the original request target, preserving both percent-encoded division and literal percent sequences. New UI requests use v2 JSON to avoid transporting programs in URLs. Response cancellation is not execution isolation: trusted scripts may do anything the host process can do. Do not expose this API publicly. Use the protected local deployment described in `WEB-E2E.md`.

Run `./build.ps1 -Target Web-CustomFunctions`. Cake runs API regressions, including real Kestrel transport tests, publishes both applications with `VITE_API_BASE_URL=/api`, then drives Chromium and Firefox against the token-protected local proxy and actual mathematical API without mocked results. This shares ports 4174 and 60997 with `Web-E2E`; run the targets sequentially. Existing focused browser tests are adapted to assert the new request bodies. The real suite checks unsaved edits, script use, saved-tab reload, byte-preserving UTF-8 import/export, real chart rendering, numerical integration, division, and independent browser contexts.

Follow-up acceptance still includes numerical-operation UI coverage for every supported method, input-method/editor interaction, and production multi-user process isolation. A native 3D chart or symbolic-algebra web implementation is not claimed by this change. Run both real suites after changing the shared proxy or execution contract.
