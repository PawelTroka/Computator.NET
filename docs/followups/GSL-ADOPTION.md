# GSL error and distribution acceptance

Roadmap item 7. The process-wide native callback records an error in the calling thread's managed boundary and returns normally; the wrapper translates errors only after the native call has returned. The existing ReturnNAN setting keeps native return-value behavior, while ShowError translates recorded errors to ArithmeticException. Host and generated TSL imports receive the same wrappers. Initialization installs the rooted callback once, not for every request. Settings changes apply to subsequent native calls, including already-compiled functions, without reinitialization; an in-flight call retains the mode captured at its managed boundary. Raw status-return APIs remain preferable for new wrappers.

The count-checked one-time refactor committed 216 host/generated-code wrapper declarations into the two existing function source files. Its temporary preparation workflow and script are removed. Ordinary builds never rewrite application source. Review the actual wrappers in this PR and require regression CI before merging.

`GSL-Distribution-Validate` builds the pinned candidate, runs existing native/numerical acceptance, stages its DLLs and provenance beside the application, clears the candidate override and launches the staged desktop. A present but invalid packaged native directory is an error, never a silent fallback. Ordinary distributions retain the embedded baseline until the explicit adoption target is selected; use this validated stage for MSI/MSIX only after review. The loader supports the staged candidate, not arbitrary unknown native libraries.

Before release: verify the exact candidate's difficult-input behavior, native dependencies, source/patch/toolchain notices and intended architectures. This PR does not assert new ARM/x86 certification, complete sandboxing, or a newly published release. GNU GSL error handling documentation: https://www.gnu.org/software/gsl/doc/html/err.html .
